# EWS — Employee Early Warning System

EWS is an AI-powered workforce intelligence platform that detects employee retention risk before it becomes turnover. It ingests survey responses, runs them through a pretrained NLP sentiment model and a zero-shot topic classifier, aggregates per-employee feature vectors over time, and classifies every employee into a **RED / AMBER / GREEN** risk zone using a trained LightGBM classifier with SHAP explainability.

Managers and HR teams get a real-time dashboard, department health rollups, personalised intervention plans generated by a connected LLM, and an AI assistant that answers natural-language questions grounded in live workforce data.

## Architecture

```
┌──────────────────────────────────────────────────────────────────────┐
│                        Next.js 14 Frontend                           │

│                   lib/api/  (feature-slice clients)                  │
└──────────────────────────┬───────────────────────────────────────────┘

┌──────────────────────────▼───────────────────────────────────────────┐
│                   FastAPI Backend  (Uvicorn ASGI)                    │
│  main.py  →  routers/  (one file per feature domain)                │
│                                                                      │
│  routers/auth  users  llm  surveys  classification                   │
│          employees  interventions  analytics  training               │
└────┬──────────────────────┬──────────────────────────────────────────┘
     │                      │
     ▼                      ▼
┌──────────┐    ┌───────────────────────────────────────────────────┐
│PostgreSQL│    │  HuggingFace Transformers  (lazy-loaded, ~500 MB) │
│  (data)  │    │  cardiffnlp/twitter-roberta-base-sentiment-latest  │
└──────────┘    │  facebook/bart-large-mnli  (zero-shot topics)     │
                └───────────────────────────────────────────────────┘
                              │
                    ┌─────────▼──────────┐
                    │  LightGBM + SHAP   │
                    │  RAG Classifier    │
                    └────────────────────┘
```

### Tech stack

| Layer | Technology |
|---|---|
| Frontend | Next.js 14, React 18, TypeScript, Tailwind CSS, Recharts |
| Backend | FastAPI, Uvicorn, Python 3.11+ |
| Database | PostgreSQL 15 (`psycopg2-binary`) |
| Sentiment | `cardiffnlp/twitter-roberta-base-sentiment-latest` — score ∈ [-1, +1] |
| Topic detection | `facebook/bart-large-mnli` — zero-shot, 7 workplace topic categories |
| ML classifier | LightGBM + `StandardScaler` + SHAP `TreeExplainer` |
| LLM (optional) | Ollama (local) **or** Anthropic Claude via `langchain-core` |
| Auth | JWT (HS256, 24-hour expiry) + bcrypt passwords |
| Rate limiting | `slowapi` (100 req/min default) |
| Scheduling | APScheduler — optional nightly classification snapshots |
| CI | GitHub Actions — pytest + ruff lint + TypeScript type-check |

## Quick start — Docker Compose

The fastest way to run the complete stack (Postgres + Backend + Frontend):

```bash
# 1. Clone and enter the directory
git clone <repo-url> && cd EWS_V5-V_6.3

# 2. Create your env file
cp .env.example .env
# Edit .env — at minimum set POSTGRES_PASSWORD, EWS_SECRET_KEY, DATABASE_URL

# 3. Start everything
docker compose up --build -d

# 4. Open
#   Frontend:  http://localhost:3000
#   API docs:  http://localhost:8000/docs
#   Health:    http://localhost:8000/health
```

To also start the optional MLflow experiment tracker:

```bash
docker compose --profile mlflow up -d
# MLflow UI: http://localhost:5001
```

Default credentials seeded on first start: **admin / admin** (change immediately via `/users`).

|---|---|---|---|

8. Managers action their plans      PATCH /interventions/{id}  {"status": "in_progress"}

## LLM configuration

EWS works fully without an LLM — all classification, sentiment, and rule-based recommendations run offline. The LLM is an optional enhancement for:

- Narrative recommendation text (`POST /interventions/generate`)
- AI assistant natural-language Q&A (`POST /assistant/ask`)
- Survey comment thematic summary (`POST /surveys/summarize`)

**Ollama (local, free)**

```bash
# Install Ollama and pull a model
ollama pull llama3

# Then connect from EWS
curl -X POST http://localhost:8000/llm/connect \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"provider": "ollama"}'
```

**Anthropic Claude (cloud)**

```bash
# Set in .env
ANTHROPIC_API_KEY=sk-ant-...

# Then connect
curl -X POST http://localhost:8000/llm/connect \
  -d '{"provider": "anthropic"}'
```

`"provider": "auto"` tries Ollama first, falls back to Anthropic if `ANTHROPIC_API_KEY` is set, then falls back gracefully to rule-based mode.

## Survey CSV format

### Upload for inference (no labels required)

```csv
employee_id,survey_date,comments,happiness_score,stress_level,department
EMP001,2026-06-01,"Team dynamic is great but workload is overwhelming",7,8,Engineering
EMP002,2026-06-01,"Feeling undervalued and unsupported by management",3,9,Sales
```

### Upload for training (labels required)

```csv
employee_id,survey_date,comments,happiness_score,stress_level,department,risk_zone
EMP001,2026-06-01,"Workload is challenging but I enjoy the work",7,6,Engineering,AMBER
EMP002,2026-06-01,"Ready to leave — no growth path visible",2,9,Sales,RED
EMP003,2026-06-01,"Very happy — great team and good progression",9,3,Product,GREEN
```

Required columns: `employee_id`, `survey_date`, `comments`
Training also requires: `risk_zone` (one of `GREEN`, `AMBER`, `RED`)
